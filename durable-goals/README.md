# durable-goals

`durable-goals` is a portable goal protocol for agents whose work outlives a
single conversation or process. It separates owner intent, activated reality,
immutable evidence, and generated status so a resuming agent does not have to
guess which prose is authoritative.

The universal harness interface is intentionally just one convention:

> Read the repository's authoritative `GOAL.md` completely before acting.

`GOAL.md` names the typed sources and precedence rules. Harnesses do not need a
plugin or vendor-specific adapter.

This project deliberately does **not** execute jobs. Schedulers, service
managers, agent loops, and deployment systems consume a resolved goal through
the Python API or CLI. Keeping execution outside the protocol makes the goal
package useful with local scripts, systemd, Kubernetes, or a future controller.

## Protocol records

- **Gateway:** the stable entry point and checksum-bound reference index.
- **Contract:** the normalized base objective, invariants, delegations, and
  evidence-based completion predicate.
- **Amendments:** an append-only JSONL owner-decision ledger.
- **Activations:** a separate append-only JSONL record of adopted amendments.
- **Evidence index:** checksum-bound references to factual evidence.
- **Status:** a disposable projection regenerated by the resolver.

An amendment declares how it may be activated, but is never edited after it is
recorded. A separate activation record adopts it. The resolver returns two contracts:

- `desired_contract` includes every recorded amendment.
- `active_contract` includes only the active amendment prefix.

This makes “the owner has changed the goal, but the change waits for a safe
boundary” a first-class state instead of an ambiguous note.

## Try the example

The package has no runtime dependencies beyond Python 3.11.

```bash
cd durable-goals
python -m pip install -e .
dgoal validate examples/model-refresh/gateway.json
dgoal status examples/model-refresh/gateway.json
dgoal resolve examples/model-refresh/gateway.json
```

Create and chain goals without starting any workload:

```bash
dgoal init goals/next \
  --goal-id next \
  --objective "Perform the next bounded objective."

dgoal chain goals/current/gateway.json goals/next/gateway.json \
  --transition-id then-next \
  --reason "Owner ordered next after current completion"
```

The successor becomes eligible only after the transition is active and the
active source contract's completion predicate is satisfied. Readiness is
reported under `status.ready_transitions`; execution remains outside this
project.

Without installing it:

```bash
PYTHONPATH=src python -m durable_goals.cli status \
  examples/model-refresh/gateway.json
```

Run the dependency-free test suite with:

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
```

The example has revision 2 recorded but pending. Its desired evaluation
threshold is `0.85`, while its active threshold remains `0.90`.

## Authority rules

1. The gateway selects one contract and one ordered amendment ledger.
2. Referenced protocol records and evidence are verified by SHA-256.
3. Amendment revisions are contiguous and deterministic.
4. Activation records must form a prefix; later intent cannot activate through
   an earlier pending boundary.
5. Amendment preconditions fail closed when the prior value has drifted.
6. Completion is evaluated from declared evidence, never from status prose.
7. Generated status is explicitly marked `authoritative: false`.
8. References are relative and may not escape the goal package.

## Completion predicates

Contracts use a deliberately small predicate language:

```json
{
  "all": [
    {"evidence": "evaluation", "field": "/metrics/accuracy", "gte": 0.90},
    {"evidence": "release", "field": "/activated", "equals": true}
  ]
}
```

Supported composition operators are `all`, `any`, and `not`. Evidence
comparators are `equals`, `gte`, `lte`, and `exists`. Fields use RFC 6901 JSON
pointers.

## Current scope

Version `0.1` resolves and validates JSON goal packages. It intentionally omits
execution, network access, mutable databases, arbitrary code in contracts, and
automatic amendment activation. Likely next protocol work includes signed
authority records, delegation resolution, supersession records, status-file
materialization, and a conformance corpus for implementations in other
languages.

## Moving to a separate repository

Everything under this directory is self-contained and imports no Pokémon
modules. It can be extracted with Git history using `git filter-repo` or a
subtree split once its API stabilizes.

See [`docs/AUTHORITATIVE_ENTRYPOINT.md`](docs/AUTHORITATIVE_ENTRYPOINT.md) for
the cross-harness convention and [`templates/GOAL.md`](templates/GOAL.md) for a
copyable gateway.

The repository-scoped `update-durable-goal` skill lives under
`.agents/skills/`, so Codex can discover it when this directory becomes a
repository root. For broader installation across ChatGPT and Codex, the same
skill can later be bundled in a plugin; the protocol and Python package remain
usable without that plugin.

See [`docs/DISTRIBUTION.md`](docs/DISTRIBUTION.md) for why the protocol remains
language-neutral, why Python is the reference implementation, and how the goal
files, wheel, skill, and eventual plugin fit together.

The single standard skill is exposed to Codex, Claude Code, Hermes Agent,
Prime Agent, and Snowflake Cortex Code without maintaining divergent
instruction copies; see
[`docs/SKILL_COMPATIBILITY.md`](docs/SKILL_COMPATIBILITY.md).
